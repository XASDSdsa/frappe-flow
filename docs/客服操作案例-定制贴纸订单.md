# 客服操作案例：定制贴纸订单从收款到发货

本文用一个完整案例说明客服在 Flow 中如何处理“巧克粉 + 客户专属贴纸”订单。客服只需要提供业务事实并在关键节点做一次整体审核；系统自动填写的内容会在审核卡片中明确显示。

## 案例资料

| 项目 | 本案例 |
| --- | --- |
| 客户 | Driven25 |
| 巧克粉 | 山东中性灰方，100 颗 |
| 巧克粉售价 | USD 4.00／颗，合计 USD 400.00 |
| 贴纸 | Driven25 专属贴纸 v1，随巧克粉使用 |
| 贴纸对客户售价 | USD 0.00 |
| 本次贴纸生产 | 1,000 张 |
| 贴纸整批实际成本 | CNY 500.00（只计入一次） |
| 发货仓库 | 大坪仓库 - LEYA |
| 默认交货日 | 开单日后第 7 天 23:59 前 |

> 本案例假定贴纸成本已通过采购或定制服务费用记账。贴纸到货入库时只记录实际数量；若成本已经记账，入库单使用 0 估值并填写“成本已在定制服务中记账”的原因，不能再次产生费用。

## 一、客服先确认客户和需求

客服对 Flow 说：

> “Driven25，100 颗山东中性灰方，配 Driven25 v1 贴纸，贴纸不收费。”

Flow 自动检查：

- 客户是否已经存在；存在时直接复用，禁止重复建档。
- 贴纸物料和版本是否已经存在；已有同一客户、同一模板、同一版本时直接复用。
- 巧克粉与贴纸是否应作为组合关系展示给仓库；只有本次明确同时出现的巧克粉和贴纸才建立或使用组合关系。

如果客户不存在，先走“创建客户档案”流程；如果是新设计或新版本，先走“创建客户贴纸”流程。贴纸档案建立只代表物料定义完成，不代表已经有库存。

## 二、收款后创建并提交销售订单

客户在外部完成付款后，客服告诉 Flow：

> “Driven25 已付款，按刚才确认的内容开销售订单。”

Flow 依次执行：

1. `preview_sales_order`：生成完整预览。
2. 客服审核一次完整卡片，重点看客户、物料、数量、单价、贴纸 0 元、仓库、交货日期和订单总额。
3. 审核通过后调用 `create_sales_order_draft` 保存草稿。
4. 再调用 `preview_document_submission` 预览提交内容。
5. 客服整体批准后调用 `submit_reviewed_document` 提交销售订单。

审核卡片必须清楚显示：

```text
🟢 客户：Driven25
🟢 巧克粉：山东中性灰方 × 100，USD 4.00／颗
🟢 贴纸：Driven25 v1 × 100，售价 USD 0.00
🟢 订单金额：USD 400.00
🟢 发货仓库：大坪仓库 - LEYA
🟢 交货日期：YYYY-MM-DD 23:59 前
🟢 订单状态：待客服整体审核
```

提交成功必须返回订单号、提交状态和下一步；失败必须返回失败原因和可执行的修复动作，不能只显示“失败”。

## 三、登记 PayPal 收款

销售订单已经提交后，客服说：

> “登记这张销售订单的 PayPal 实际收款。”

调用 `paypal_receipt_procedure`，填写真实的 PayPal 交易号、总额、手续费、净额和收款日期。当前规则为：

- 只接受 USD 收款。
- 收款必须关联已提交的销售订单。
- 总额、手续费和净额必须能对上 PayPal 记录。
- 相同交易号不能重复登记。
- 未找到订单或金额不一致时停止并说明原因，不能创建一笔“无归属收款”来掩盖问题。

## 四、等待贴纸生产完成

销售订单中的贴纸行是售价 0 元，不能据此增加库存。生产中只能保留订单、采购或定制服务记录：

- 未到货前不能创建可出库的贴纸库存。
- 不得用“预计生产数量”冒充库存。
- 贴纸成本如果已经在定制服务中记账，后续入库只记录数量，不再次记费用。

## 五、贴纸实际到货后入库

贴纸真正到货后，客服说：

> “Driven25 v1 贴纸实际到货 1,000 张，入库大坪仓库 - LEYA。”

Flow 先调用 `get_purchase_receipt_options` 找到准确物料和仓库，再调用 `preview_purchase_receipt` 生成预览。客服审核：物料、版本、数量、仓库、成本口径和是否实际到货。

入库分两种情况：

1. **成本尚未记账**：填写真实供应商、真实单位成本和实际到货，按正常采购入库提交。
2. **成本已在定制服务中记账**：单位估值可以为 0，但必须填写明确原因，例如“本批贴纸整批成本 CNY 500 已在定制服务记录中记账，本次仅补充实物库存”。这不会再次减少现金或应付。

只有实际到货且审核通过后，才调用入库保存/提交工具。部分到货只能入库实际数量，剩余数量继续等待。

## 六、创建出库单

贴纸库存足够、销售订单已提交且收款状态符合出库规则后，客服说：

> “准备 Driven25 这张订单出库。”

Flow 调用 `get_delivery_note_options`，只展示这张订单的待出库行：

```text
待出库：
1. 山东中性灰方 + Driven25 v1 贴纸：100 套
贴纸库存：1,000 张，可满足本次 100 张
```

客服可以回答“全部出库”或指定行和数量。Flow 不能把全部数量静默当作客服选择，也不能悄悄删除贴纸行。

随后执行：

1. `preview_delivery_note`：显示客户、销售订单、发货仓库、每一行数量、贴纸对应关系和库存校验。
2. 客服审核一次完整预览。
3. `create_delivery_note_draft`：创建出库单草稿。
4. `preview_document_submission` → `submit_reviewed_document`：审核后提交出库单。

贴纸库存不足时，ERPNext 原生校验必须阻止出库并列出短缺数量；不能通过删行、改数量或临时 0 库存绕过。

## 七、创建运单并发货

出库单提交后，才进入运单流程：

1. 先创建系统中的通用 Shipment，保存出库单、客户、包裹和物流服务商信息。
2. 选择顺丰或其他服务商。
3. 选择顺丰时，才调用顺丰服务商接口创建面单、查询轨迹或查询运费。
4. 其他服务商没有接口时，只填写服务商和已有单号，运费由人工登记并说明来源。
5. 打印/打开面单不等于已经交给承运商；客服确认实际交运后，才标记发货。

运单创建失败必须返回接口错误和下一步；拿到单号不代表已发货，接口“尝试成功”也不能直接改变出库单和销售订单状态。

## 八、复购订单怎么处理

如果 Driven25 再次使用同一款 `v1` 贴纸：

- 直接复用同一个客户贴纸物料和版本。
- 不重复收取贴纸服务费，也不重复计入已经发生的整批成本。
- 新订单仍按实际需要数量检查贴纸库存。
- 库存足够即可继续出库；库存不足时可以先做订单，但出库单提交会被原生库存校验阻止，直到实际入库。

如果客户要求新图案、新模板或新版本，则建立新的贴纸物料/版本，并对新的生产批次单独记录一次真实成本。

## 不可绕过的防错规则

| 检查点 | 不满足时的处理 |
| --- | --- |
| 客户不明确 | 停止，不创建可能重复的客户 |
| 新贴纸没有图片、模板或版本 | 停止创建贴纸档案 |
| 销售订单未整体审核 | 只保留草稿，不提交 |
| PayPal 无真实交易号或币种不是 USD | 不登记收款 |
| 贴纸尚未实际到货 | 不增加库存，不允许贴纸出库 |
| 贴纸库存不足 | 出库提交失败，显示短缺数量 |
| 订单行与贴纸对应关系不清楚 | 退回客服补充，不自动猜测 |
| 面单接口只返回尝试成功 | 保留待确认状态，不标记已发货 |
| 已登记的贴纸成本再次入库 | 要求说明成本已记账，避免重复计费 |

## 客服最终只需记住

1. 先确认客户和贴纸版本，再确认订单。
2. 客户付款后创建并提交销售订单，再登记真实 PayPal 收款。
3. 贴纸生产完成并实际到货后才入库。
4. 贴纸成本只记一次；已记账的批次入库只补数量并写明原因。
5. 出库前必须看清待出库产品和贴纸数量，库存不足不能绕过。
6. 出库单提交后才创建运单；拿到单号不等于已经发货。
7. 每个关键写入动作都先看完整审核卡片，再一次批准。
