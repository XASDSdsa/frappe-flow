# 出库单创建顺丰面单：客服操作流程

已于 2026-09-17 随 r56 上线并启用，绑定 Flow 与销售助理；发布验证没有实际创建顺丰面单。

## 客服实际操作

1. 告诉销售助理：“给出库单 XX 创建顺丰面单”。出库单必须已经提交；草稿先按正常出库审核提交，此工具不会代为扣库存。
2. 助理自动核对客户、商品、仓库、已有运单和权限。已创建面单的直接返回原单；处理中或结果待核对的保留原记录，不能再下一个。
3. **客服选地址**。有匹配历史地址时优先展示并用“🟢 历史成功下单地址 · 优先推荐 · 仍需客服选择”标记。没有历史时自动用国家、邮编向顺丰反查，AI 从真实返回的候选中推荐；地区不同处必须明确展示。
4. 回复“选 A1”即可。若包裹缺少信息，同一次补充，例如：“选 A1，1 箱，长30宽20高15厘米，每箱2.5千克”。已有真实数据自动带入，不能猜重量或尺寸。
5. **整体批准一次**。检查完整客户/商品/收发地址与电话、仓库、包裹、顺丰产品、申报金额币种和品名。预设值会展示供核对；不需要每项单独确认。错误则拒绝并说明修改内容。
6. 查看最终结果。只有顺丰实际返回单号，才显示“单号已创建”；PDF 生成后提供“打开面单”。检查并打印后再按正常流程交给物流；创建面单不代表包裹已发出。

常规查询和预检自动完成，每次集中显示每个步骤的结果及原因。需要客服参与的正常节点只有地址选择和最终整体批准；确实缺资料时一次列齐。

## 地址规则

- 历史匹配基于当前地址的国家、邮编和完整街道；取消、候选、无真实单号或无读取权限的历史不可推荐。
- 只复用历史地区信息，联系人和电话取当前资料。地址记忆与有可读成功单据的历史分开标记。
- 即使历史只有一条，客服仍须明确选择。系统不会将“找到历史”当作“已选择”。
- AI 只筛选并解释顺丰实际候选；后台按候选编号带入省、市、区县，不接受 AI 编造的地区。
- 美国 ZIP+4 若顺丰只返回匹配的 ZIP5 地区，显示提示，保留原完整邮编；不接受其他邮编。
- 街道或邮编本身错误须先修正地址档案，再重新准备候选；不在聊天参数里悄悄改收货地点。
- 无匹配候选时明确说明原因并停止，不靠猜测下单。只有成功下单后原生机制才尝试记忆地址，预检不写地址档案。

## 结果提示

| 提示 | 含义与下一步 |
| --- | --- |
| 待选择 | 显示真实地址候选，客服回复编号；必要包裹数据一次补齐。 |
| 待批准 | 资料已预检，尚未保存或向顺丰下单；整体审核一次。 |
| 已排队／处理中 | 本地运单与下单记录已保存，尚不能宣称顺丰创建成功；只查看原结果。 |
| 已取得单号，PDF 未就绪 | 面单已创建，保留原单号；稍后在原运单打印，不重新下单。 |
| 单号及 PDF 已就绪 | 展示真实顺丰单号和面单链接，核对后打印。 |
| 结果待核对 | 请求异常或任务中断，保留原下单记录，核对顺丰和系统历史，不自动重下。 |
| 批准后资料变化 | 明确变化原因，阻止按过期方案请求顺丰；从原运单核对处理。 |

## 实现与启用

导入入口 `flow.integrations.erpnext.sf_label_flow`：

- `prepare_sf_label`
- `list_sf_label_addresses`
- `preview_sf_label`
- `create_sf_label`（唯一需要一次系统批准的工具）
- `get_sf_label_result`

准备/审核令牌绑定网站、登录用户和对话，30分钟有效。审批后锁定出库单并复核最新信息，通过原生出库单→运单转换和权限保存、提交运单。不会提交出库单、替换旧面单或取消物流。

后台任务在本地事务成功提交后开始；记录唯一请求并在请求顺丰前留下持久执行状态。重复工具调用返回原单。后台请求不自动重试，原生面单历史保留承运商响应与结果不明状态。PDF 失败独立报告，不能撤销或掩盖已经创建的单号。

代码部署后显式启用：

```sh
bench --site <站点> execute flow.integrations.erpnext.sf_label_install.install_sf_label_tools --kwargs '{"enable": true}'
```

此命令注册 Imported 工具并绑定 Flow 与销售助理。迁移只刷新已注册工具，不会自动开启此前未启用的功能。需要站点配置正常的后台任务队列、顺丰接口与客服运单创建/写入/提交权限。正式环境尚需以真实权限做一次联调；本地测试不会请求顺丰或创建真实面单。
