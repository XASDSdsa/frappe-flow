# Flow 出库单创建流程

本流程创建 ERPNext 出库单草稿。保存草稿不等于实际发货，后续提交出库单、扣库存和创建物流运单分别处理。

## 客服操作

1. 说明订单号；仅说明客户时，系统列出当前账号可读订单，多个订单需要选清楚。
2. 系统核对订单存在、已提交、未取消/关闭/暂停、仍有待出库商品，以及实际收款。表格列出行号、商品（含已有贴纸）、单位、订单数量、已出库、草稿占用、本次可出库及仓库。
3. **客服明确选择**，例如“第1行出40颗，第5行出40张”，或者“全部出库”。系统不会默认全选，也不会擅自添加没有选中的贴纸。“全部”只包含本次可选剩余数量，不重复包含其他草稿占用。
4. 系统展示完整出库摘要：订单、客户、本次明细、数量、仓库、收货地址、收款情况和金额。整体批准一次后保存草稿；需要修改就拒绝并说明，再预检审核。
5. 成功返回真实出库单链接；失败说明具体步骤、原因、是否回滚及应处理的事项。

## 收款规则

- 全款：正常选品、审核。
- 部分收款：允许继续；橙色提示已收金额和未收余额，由客服整体审核批准。
- 完全未收款：明确提示并停止，不当作已收款订单。
- 零金额订单：注明无需收款，仍须选品和审核。
- 只汇总本单关联的已提交有效收款；排除取消凭证及无银行/现金科目的日记账核销，退款抵减。预收款转发票后同一账务行只计算一次。无法明确归属的跨订单/合并发票收款、无法核实的币种转换会说明原因并停止，不能猜金额。

## 数量与草稿保护

- 按订单明细行识别。同商品不同价格或仓库仍是不同订单行。
- 可出库数量使用原生累计出库数量，退货不重复扣减；再扣除已有有效出库草稿的占用。
- 原有草稿仅向有读取权限的客服展示链接；无权读取的草稿仍参与数量保护。
- 保留原订单价格、仓库、销售团队、币种和地址。组合包由原生规则按所选数量生成组件。
- 不允许超出剩余数量、负数、零数量或违反单位整数要求。供应商直发和数量未确定的订单行不自动转普通出库。
- 预检方案30分钟有效，绑定本人及当前对话。保存前锁定订单，重新核对收款、数量和其他草稿；变化后重新选择并审核。同一已完成方案返回原单，失败撤回本次写入。
- 草稿不实际预留或扣减库存，实际库存、批次及序列号仍须按原生提交出库流程核验。

## 客户贴纸库存保护（2026-09-18）

- 仅客户贴纸增加库存及成本硬校验；巧克粉与其他物料保留当前原生库存规则，全局允许负库存设置不变。
- 新贴纸明确开启维护库存。已有非库存贴纸必须通过原生物料校验修正；不绕过已有交易对物料类型变更的限制。
- 档案和图片创建、客户付款、采购订单都不增加库存。真实到货后，通过原生采购收货记录实际合格数量及真实成本。
- 出库草稿保存、Flow预检和提交都检查指定仓库库存；重复商品行及原生组合包组件按库存单位合计。提交重新读取并锁定库存记录，防止同时出库重复使用库存。
- 缺货时显示需要、可用、缺少数量；不自动减少数量、不删除贴纸、不用零估值放行。成本缺失时提示核对真实采购入库。
- 退货入库和已提交单据的非库存更新不重新扣减或校验已经消耗的库存。草稿不实际预留库存，提交时可能因库存变化而阻止。
- 客户贴纸识别沿用标准变体及现有精确旧编码规则；本次未清理或伪造旧库存、采购单或成本。
